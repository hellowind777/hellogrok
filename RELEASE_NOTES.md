# Release Notes — v0.1.31

## Contradictory provider usage reports no longer inflate Grok Build's context meter or fire premature auto-compact

- **The failure this fixes is a misreported number, not a misconfigured threshold.** Grok Build feeds the `total_tokens` a provider reports straight into its context meter and its `auto_compact_threshold_percent` check, with no cross-check against what was actually sent. Relays occasionally return a usage object whose prompt count double-counts the cached prefix — or reports session-cumulative prompt tokens — in a single response. One such report took a verified session at roughly 45% of its window to 91% in one step and launched a multi-minute compaction of a history that never needed compacting; the compaction itself then cost minutes on a slow channel.

- **hellogrok now cross-checks every usage report against the physical request.** For each conversation (keyed by channel plus the client's session identity, which Grok Build supplies on every request), the proxy learns a bytes-per-token ratio from the first coherent report: the tokenizable footprint of the request body — encoded size minus embedded base64 data URIs, which carry image bytes at a nearly constant token cost — divided by the reported prompt tokens. Any later report whose prompt count exceeds 1.25× what the current body can hold is contradictory by construction and is dropped wholesale, leaving Grok Build on its own byte-based estimate until the provider reports coherently again. A request body that shrinks by more than a quarter (compaction, rewind, resume) relearns the baseline instead of treating the new, smaller context as an over-report.

- **The check covers every wire path and stays out of the way otherwise.** Native Chat Completions passthrough (streaming and buffered), native Responses passthrough (streaming and buffered, ahead of the `context_details` projection so a bad report cannot survive inside it), and both translated paths (Messages and Chat into Responses, streaming and buffered) all route through the same guard. Conversations without a stable session identity skip the check entirely, so behavior for clients that supply no identity is unchanged; coherent providers are never touched, because the guard only ever suppresses reports that overshoot the body-derived expectation and never rewrites a number. Billing-facing fields are left as reported wherever the report is coherent.

- **Verified by tests, including an end-to-end replay of the incident shape.** Unit tests pin baseline learning, suppression of a doubled report, recovery on the next coherent report, baseline relearning after a context rewrite, and per-channel/per-session isolation. Two end-to-end tests drive real SSE upstreams whose second call doubles the prompt count — one on the native Chat path, one on the native Responses path — and assert the downstream stream carries `usage: null` while assistant content survives intact. The full suite passes.

Restart both hellogrok executables after upgrading.
