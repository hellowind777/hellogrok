# Release Notes — v0.1.10

## Context accounting and compaction now follow Grok Build's native contract

hellogrok now supplies `usage.context_details` for every channel that returns a complete trustworthy input/output pair, including common `prompt_tokens` / `completion_tokens` and detail aliases. Missing, conflicting, fractional, overflowing, or placeholder usage remains null, so Grok Build keeps its prior live-context baseline instead of resetting it to zero.

Capacity discovery is configuration-driven rather than model-ID-driven. Explicit model or provider limits remain authoritative; otherwise valid upstream `X-Grok-Context-Window` and `X-Grok-Max-Completion-Tokens` metadata, or one unambiguous structured context-limit field, can describe the route. Grok Build's catalog remains the fallback. A restored session already above its threshold therefore compacts before the next user prompt across Responses, Messages, and Chat Completions.

## Output reservations no longer masquerade as a smaller context window

DeepSeek's documented 1M context includes both input and generated output, while its 384K output cap includes reasoning and visible text. When the provider proves that the current request fails only because Grok Build reserved the full output allowance, hellogrok reduces that request to the exact remaining space and retries once. The retry requires a self-consistent HTTP 400 `invalid_request_error`; ambiguous, conflicting, exhausted, malformed, and repeated failures pass through unchanged.

Responses `status = "incomplete"` and Chat `finish_reason = "length"` now retain the provider's partial result with a canonical `max_output_tokens` reason. Exhausting a per-response output allowance is kept separate from exhausting the total live context.

## Reasoning configuration is compact and user-owned

The generated DeepSeek menu is now one native line:

```toml
reasoning_efforts = ["none", "low", "high", "max"]
```

hellogrok no longer writes redundant `supports_reasoning_effort` or four repeated object tables. Existing user lists, empty lists, custom labels, order, and defaults are never replaced or extended. Only the exact verbose menu generated by older hellogrok versions is migrated once, with the previous High default preserved.

## Third-party channels retain Grok Build local tools

Responses, Messages, and Chat Completions bridges preserve arbitrary Grok Build function tools and their history, including shell, file, patch, task, and MCP functions. Third-party request wires consistently remove xAI-only `x_search` without removing ordinary functions or provider `web_search`.

First-party DeepSeek Responses and Messages hosted-search requests now stay on their configured native APIs. DeepSeek Chat defaults to the provider's officially supported Responses API, while an explicit `chat_search_dialect = "messages"` remains available.
